01

Python / IT support

Open GitHub

Tibs Diagnostic Toolkit

I built this as a practical support tool rather than a portfolio decoration. The idea is simple: when a device or connection is acting up, run one tool, collect the basic facts and export a report that can be reviewed properly.

What it does

  • Checks whether the internet is reachable without relying only on DNS.
  • Tests DNS resolution, latency and packet loss.
  • Detects local IPv4 and gateway details where the platform allows it.
  • Collects system information such as CPU, memory and storage details.
  • Creates timestamped reports for troubleshooting records.

What it shows

  • Python scripting for a real support workflow.
  • Cross-platform thinking across Windows, Linux and Android Termux.
  • Testing discipline with regression, fuzz and concurrency checks.
  • Defensive programming when commands or permissions are missing.

Open site

ValuTints website

This was a family business website, which meant the site had to be practical before anything else. Visitors needed to understand the services, see examples of the work and find a clear way to get in contact.

What I handled

  • Page structure for services, gallery content, contact and business information.
  • Responsive layout so the site works properly on phones and desktop screens.
  • Copy and contact flow organised around the actual business.
  • Iteration from feedback so the design stayed consistent across pages.

Why it matters

  • It is a real website for real people, not a fake landing page.
  • It demonstrates HTML, CSS, JavaScript, deployment preparation and maintenance.
  • It gave me practice translating a business need into a usable site.

Self-hosting

Nextcloud self-hosted server

I hosted a private cloud storage service using Nextcloud and Docker on my own hardware. The project fed into my dissertation work and taught me how different a system feels when I am responsible for access, storage and maintenance.

What I worked with

  • Nextcloud for personal cloud storage.
  • Docker for service deployment.
  • Tailscale for private remote access.
  • Port forwarding as a comparison point for public exposure.

What I learned

  • Remote access is a security decision, not just a convenience.
  • Documentation matters when rebuilding or debugging a service.
  • Self-hosting makes networking and storage concepts much more concrete.
