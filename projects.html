Tibs Diagnostic Toolkit

I built Tibs Diagnostic Toolkit as a small first-line troubleshooting tool. The goal is to collect useful checks quickly, save the results, and make it easier to explain what has already been tested.

The tool is written in Python and is designed to work across Windows, Linux, and Android through Termux. It checks internet reachability, DNS resolution, gateway and IPv4 details where available, latency, packet loss, system information, storage, and website reachability.

What I focused on

  • Making the checks useful for real troubleshooting.
  • Handling missing commands or restricted platforms without crashing.
  • Creating timestamped reports that can be saved and reviewed.
  • Keeping the tool simple enough to run quickly.

What I learned

  • How to structure a practical CLI tool.
  • How different platforms expose system and network information.
  • Why defensive error handling matters in support tools.
  • How testing helps stop old fixes from breaking again.

Self-hosting · Docker

Nextcloud self-hosted server

I hosted a private cloud storage service using Nextcloud and Docker on my own hardware. This project helped me understand what is involved in running a service myself rather than just using a finished product.

I worked with container setup, user access, storage planning, local networking, Tailscale for private remote access, and port forwarding as a comparison point for exposing services publicly.

Tools and topics

  • Nextcloud for private file storage.
  • Docker for containerised deployment.
  • Tailscale for remote access without opening public ports.
  • Port forwarding and the security trade-offs around exposure.

What I learned

  • Remote access is a security choice, not just a convenience.
  • Documentation matters when rebuilding or troubleshooting.
  • Self-hosting makes storage, networking, and updates feel much more real.
